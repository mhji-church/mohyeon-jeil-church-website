# 회원 이름 로그인과 직접 비밀번호 재설정

## 현재 절차

2026-11-03 사이트 운영자의 요청으로 관리자 요청 단계를 제거했다.

1. /member/recovery에서 가입한 이름과 생년월일 6자리 문자열을 입력한다.
2. 새 비밀번호·확인값을 입력해 바로 변경한다.
3. 이름 또는 기존 아이디와 새 비밀번호로 로그인한다.

문자·이메일·관리자 승인 단계를 사용하지 않는다. 새 유료 서비스 가입이나 실제 문자 발송도 없다. **이름·생년월일을 아는 타인이 비밀번호를 변경할 수 있는 낮은 신뢰도의 재설정 방식**이다. 일회용 쿠키와 횟수 제한이 이 본질적인 위험을 없애지는 않는다. 강한 본인 인증을 완료했다고 표현하지 않는다.

## 이름 로그인 유지

- 이름은 NFKC·앞뒤 공백·연속 공백 정규화 후 완전 일치로 비교한다.
- 기존 아이디와 다른 회원 이름이 충돌하면 아이디를 우선한다. 이름 자체를 아이디로 만든 계정은 동명이인 검증을 생략하지 않는다.
- 비밀번호로 여러 대표 회원이 인증되면 선택하지 않는다. 후보 목록을 공개하지 않는다.
- 병합 대표 이름은 같은 통합 회원의 활성 별칭 자격 증명을 사용한다. 원본에만 남은 다른 이름은 해당 원본의 자격 증명만 허용한다. 기존 아이디는 대응하는 비밀번호 해시만 검증한다.
- 대표 회원·IP 기준 실패 기록, 15분 실패 집계 구간, 5회 실패/5분 제한과 남은 시간 표시를 유지한다. 재설정만으로 진행 중인 로그인 제한을 지우지 않는다. 기존 15분 제한 기록도 임의 변경하지 않는다.

## 대상 결정과 일회용 권한

- 저장된 유효한 YYYY-MM-DD에서 YYMMDD를 만들며 입력에서 출생 세기를 추정하지 않는다. 앞자리 0을 보존한다.
- 이름·생년월일로 한 대표 회원이 확인될 때만 권한을 생성한다. 미등록·불일치·동명이인·서로 다른 세기의 같은 YYMMDD 등으로 모호하면 임의 선택하지 않는다. 병합 원본들이 같은 대표 회원으로 확인되면 한 통합 계정으로 처리한다.
- 중지 회원·관리자 아이디와 충돌하는 계정에는 권한을 만들지 않는다. 관리자 인증 저장소는 일반 회원 저장소와 분리되어 있다.
- 무작위 256비트 토큰을 HttpOnly·SameSite=Strict 쿠키에만 저장한다. 운영에서는 Secure를 사용하고 경로를 /api/members/recovery로 제한한다. JSON·URL·분석·애플리케이션 로그에 토큰을 전달하지 않는다.
- DB에는 SHA-256 토큰 해시·내부 회원 ID·세션 버전·5분 만료 시각만 저장한다. 회원당 권한 하나로 제한하고 새 발급 시 이전 권한을 대체한다.
- 첫 응답과 쿠키 형태는 미등록·모호·일치 모두 동일하다. 따라서 새 비밀번호 입력 화면에 진입했다고 정보 일치나 본인 인증이 확정된 것은 아니다. 실제 변경 시 DB 권한이 없으면 동일한 오류로 거부한다.
- 클라이언트가 회원 ID나 verified 값을 넘겨 대상을 바꿀 수 없다. 완료 API는 서버 쿠키만 사용한다.

## 원자적 변경과 기존 기능

- 새 비밀번호는 기존 6~72자 정책과 PBKDF2 해시 방식을 사용한다. 비밀번호 확인·보기/숨기기를 지원한다.
- 완료 트랜잭션 안에서 만료·회원 상태·세션 버전을 다시 확인한다.
- 대표 회원·병합 원본·모든 로그인 별칭의 해시를 함께 변경하고 세션 버전을 증가시킨다. 비활성 별칭을 활성화하거나 승인 상태·권한을 바꾸지 않는다.
- 사용한 재설정 권한과 관련 잔여 권한은 같은 트랜잭션에서 삭제한다. 재사용은 거부한다. 일반 비밀번호 변경·관리자 임시 비밀번호 발급도 남은 권한을 무효화한다.
- 비밀번호·권한 소비·세션 폐기·활동 기록 중 실패가 있으면 전체 롤백한다. 쓰기 자동 재시도는 없다.
- 탈퇴 시 이 테이블도 삭제하고 FK로 보호한다. 탈퇴한 계정을 복원하는 수단으로 사용할 수 없다.
- 기존 관리자 임시 비밀번호 발급 기능 자체는 유지하지만 공개 재설정의 필수 단계가 아니다. 이전 재설정 요청 패널은 제거했다.

## 요청 보호와 보관

- 시작·완료 API 모두 동일 출처 JSON과 실제 본문 1KB 제한을 적용한다.
- 시작/완료에 로그인과 별개의 IP 제한을 적용한다. 15분 집계 구간의 다섯 번째 요청부터 5분 대기하며 Retry-After를 반환한다. 제한 재시도로 만료를 연장하지 않는다.
- 응답은 private, no-store이며 기존 서비스워커의 API 캐시 제외 정책을 유지한다. /member/**와 /api/**는 기존 방문 통계 수집에서 제외된다.
- 미사용 권한은 최대 회원당 1행이며 만료 후 사용할 수 없다. 유효한 신규 발급 시 만료 행을 정리한다. 사용 완료·일반 비밀번호 변경·관리자 초기화·탈퇴 시 삭제한다.
- 추가형 0006_member_recovery_grants.sql은 임시 DB에서만 적용했다. 이전 0005 요청 테이블과 마이그레이션은 호환을 위해 보존하며 새 공개 요청은 생성하지 않는다.
- 코드 롤백 시 회원 원본/기존 컬럼을 삭제할 필요는 없다. 운영 적용은 별도 배포 승인 뒤 진행해야 한다.
