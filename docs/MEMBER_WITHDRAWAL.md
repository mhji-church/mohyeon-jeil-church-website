# 회원 본인 탈퇴

## 사용자 절차

`/member`의 개인정보·비밀번호 변경 영역 아래에 작은 `회원 탈퇴` 버튼을 표시한다. 확인창에서 현재 비밀번호와 `탈퇴 안내를 확인했습니다` 체크를 모두 입력해야 실행할 수 있다. 취소가 기본 포커스이며 취소·닫기·ESC는 서버 요청을 보내지 않는다. 비밀번호는 창을 닫으면 메모리에서 비우고 저장하지 않는다.

서버는 일반 회원 세션만 사용한다. 요청의 회원 ID·이름·생년월일·전화번호·인증 완료 표시 등은 받지 않는다. 관리자 로그인 쿠키만으로 실행할 수 없고 관리자 자격 증명 저장소는 삭제 대상이 아니다. 일반 회원 계정에 관리자와 같은 문자열의 아이디가 있더라도 별개의 일반 회원 ID만 대상이 된다.

## 서버와 트랜잭션

- API: `POST /api/members/withdrawal`, 동일 출처 JSON, 본문 실제 바이트 최대 1KB. 본문은 `password`, `confirmed: true` 두 항목만 허용한다. 응답은 `private, no-store`다.
- 검증된 세션의 대표 회원 ID와 세션 버전을 읽고, 쓰기 트랜잭션 안에서 회원 존재·버전·상태·병합 상태·비밀번호를 다시 확인한다. 기존 PBKDF2 해시 검증을 재사용한다. 병합 회원은 같은 대표 회원의 활성 별칭 비밀번호만 허용한다.
- 탈퇴 재인증은 로그인과 별도의 대표 회원/IP 해시 키로 제한한다. 15분 실패 집계 구간에 5회 실패 시 5분 대기하며 Retry-After를 반환한다. 제한 중에는 올바른 비밀번호도 거부하고 만료 시각을 연장하지 않는다. 요청·취소 자체로 로그인 제한을 만들지 않는다.
- 삭제·기록 비식별 처리·필수 탈퇴 로그 저장은 하나의 명시적 쓰기 트랜잭션이다. 어느 단계에서든 실패하면 롤백한다. 쓰기 자동 재시도는 없다. SQLite가 동시 두 번째 쓰기를 즉시 거부하면 일반적인 재시도 오류를 반환하고, 추가 삭제를 수행하지 않는다.
- 병합 취소나 다른 병합이 세션 검증 뒤에 실행되면 트랜잭션의 버전·대표 계정 확인으로 재로그인을 요구한다. 연관관계 목록은 쓰기 잠금 안에서 다시 읽는다.
- 현재 스키마의 회원 참조 테이블과 FK를 조사했다. 미검토 회원 ID 참조 테이블이 추가되었으면 삭제를 중단한다. 커밋 직전 foreign_key_check도 확인한다. 런타임 DDL이나 새 마이그레이션은 없다.

## 삭제되는 자료

- 현재 대표 회원과 활성 병합 관계에 연결된 원본 회원 행 전체: 이름·아이디·연락처·생년월일·직분·소속·비밀번호 해시/솔트 등.
- 대표/원본 회원의 모든 로그인 별칭(비활성 별칭 포함), 세션 버전, 아카이브 권한, 비밀번호 재설정 요청과 일회용 재설정 권한.
- 해당 회원 ID에 소속된 성도사업장 신청서 전체(신청자·주소·연락처·소개·관리 메모 등).
- 해당 회원의 병합 원본 스냅샷·원본 권한 스냅샷. 빈 병합 그룹도 삭제한다. 일부 다른 회원의 이력이 남는 과거 비활성 그룹은 대상 스냅샷만 지우고 그룹의 복원 프로필을 비워 탈퇴 회원을 복원하지 못하게 한다.
- 현재 요청의 탈퇴 재인증 제한 키.

회원이 물리적으로 없어지므로 모든 기기의 서명된 기존 세션은 조회 시 즉시 무효가 된다. 이름·옛 아이디·병합 별칭으로 예전 계정에 로그인하거나 재설정을 요청할 수 없다. 이후 재가입은 새 랜덤 회원 ID와 승인 대기 상태를 사용하며 권한·병합·과거 세션을 상속하지 않는다.

## 보존과 비식별 처리

- 관련 관리자/로그인/아카이브 활동 기록은 행·시각·작업 코드를 보존한다. 관련 메타데이터와 아카이브 요약은 비우거나 `탈퇴 회원 관련 기록`으로 바꾼다. 회원 행위자와 대상은 기존 ID로 역추적할 매핑이 없는 새 `withdrawn:<UUID>`로 대체한다. 관리자 행위자는 유지한다. 회원 로그인 이력의 IP·기기 메타데이터도 제거한다.
- 필수 `member.withdrawal` 이벤트에는 처리 시각·성공 결과와 비식별 내부 참조만 남긴다. 이름·전화번호·생년월일·비밀번호·세션/재설정 토큰을 기록하지 않는다. 관리자 활동 기록에서는 `회원 본인 탈퇴`, `탈퇴 회원`으로 표시한다. 기존 활동 기록 권한은 변경하지 않는다.
- 관련 로그 식별은 회원/병합/신청 내부 ID와 고유 로그인 아이디를 기준으로 한다. 동명이인이나 공용 휴대폰이 같다는 이유로 다른 회원 자료를 일괄 지우지 않는다.
- 단순히 중복 의심으로 분류된 다른 회원, 이미 작성된 교회 공용 게시물·주보·갤러리·예배/출석 영상·공개 성도사업장 게시물·R2 이미지 파일은 유지한다. 기존 신청서를 공개 콘텐츠로 전환한 게시물도 별개 공용 콘텐츠로 취급한다.
- 이전 로그인/재설정 제한의 일방향 해시와 횟수·만료 시각은 원본 IP나 회원 프로필/비밀번호가 없고 역참조 테이블도 없다. 기존 보관 방식대로 남을 수 있으나 새 회원 ID의 로그인 권한이나 계정을 복원하지 않는다.
- 진행 중이던 로그인 기록·권한 부여·사업장 신청 쓰기는 INSERT 시점의 회원 존재를 함께 확인하여 탈퇴 후 지연된 요청이 개인 자료를 다시 생성하지 않도록 한다.

## 검증 원칙

임시 DB와 가상 계정으로만 검증한다. 운영 회원 탈퇴·승인·병합·비밀번호 변경·운영 DB/R2 작업은 실행하지 않는다. 계정 삭제 성공 뒤 쿠키를 제거하며 완료 화면으로 포커스를 이동한다. 실패에는 성공 안내를 표시하지 않고 사용자가 재시도할 수 있는 오류를 보여 준다.

배포·운영 마이그레이션은 이번 작업에 포함하지 않는다. 공유하는 재설정 테이블의 `0005_member_password_reset_requests.sql`과 `0006_member_recovery_grants.sql`은 여전히 임시 DB에만 적용된 상태다.
